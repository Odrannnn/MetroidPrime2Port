# Releasing

How a release of the port is built, what it may contain, and what has to travel with it. Mirrors
`../MetroidPrimePort/docs/RELEASING.md`, for the platforms this tree builds: Linux, Windows
(x64, arm64), macOS (arm64, experimental), Android, a Flatpak bundle and iOS (unsigned,
experimental).

## What may ship

The binary and the port's own files, nothing of the game's: no disc image, no DOL or REL, no
extracted PAK/STRG data, no bytes copied out of the executable. The port reads the user's own disc
at run time. `LICENSE` (MIT) covers only this project's own work; `NOTICE` says what it does not
cover (`src/`, `include/`, `extern/sdk/`, `config/`) and lists the third-party terms.
`LICENSE-decomp` is upstream PrimeDecomp's dedication, kept as it was.

Every package carries `LICENSE`, `NOTICE` and the third-party notices:
`share/licenses/metroid-prime2-port/` in the AppImage and the tarball (`tools/collect_licenses.sh`,
Dawn and nod from `packaging/licenses/`, whose prebuilt archives carry none), and `assets/` in the
APK (Gradle's `syncLicenseNotices`). The Flatpak collects them in the manifest's `post-install`
(vendored snapshots from the tree, `packaging/licenses/`, and the fetched dependencies by glob, since
those exist only once `cmake-ninja` has run); it bundles no shared libraries, the runtime supplies them.

Desktop packages (tarball, AppImage, Windows zip, macOS bundle, Flatpak) carry no loose `textures/`:
the button glyphs and binding icons (generated by `tools/make_prompt_glyphs.py`, committed) are built
into the executable (`MP_EMBED_RESOURCES`, MP1 `ce0bf885e`). Only the APK ships them, as `assets/textures`
(unpacked to `<files>/textures` at start). Rebuild, don't just recopy, after changing `kKeys`.

## CI

| Workflow | Trigger | Produces |
|---|---|---|
| `linux-build.yml` | PRs, manual (a push starts nothing) | Ubuntu 24.04, gcc-14; build, `ctest -L port`, Aurora `gx_fifo_tests` (`.github/actions/build-and-test`) |
| `linux-release.yml` | manual | `almalinux:9` + gcc-toolset-14, x86_64 and aarch64; AppImage + tarball + split-off `.debug` (RelWithDebInfo, stripped binary, as MP1), artifacts `metroid_prime2_port-linux[-aarch64]`; fails if the binary needs glibc > 2.34 or GLIBCXX > 3.4.29 |
| `tools/make_flatpak.sh` | manual, local | `build/flatpak/MetroidPrime2Port.flatpak` (app id `io.github.odrannnn.metroidprime2port`, `org.freedesktop.Platform` 25.08); `flatpak/*.yml` builds the committed `port` branch offline from pinned sources (Dawn, nod, SDL and the Aurora dependencies, `disable-submodules`); stops if the newest metainfo release differs from `versionName` |
| `windows.yml` | manual | clang-cl, x64 and arm64 (`windows-11-arm`); artifacts `metroid_prime2_port-windows[-arm64]` (`dist/`) |
| `macos.yml` | manual | arm64, ad-hoc signed `Metroid Prime 2 Port.app` + `licenses/`, artifact `metroid_prime2_port-macos`; checks system-only dylibs, codesign and the packaged no-disc startup |
| `ios.yml` | manual | unsigned `MetroidPrime2Port.ipa` (iphoneos, ad hoc signed inside; users sideload it), artifact `metroid_prime2_port-ios`; checks system-only libraries |
| `android.yml` | manual | release APK signed with this project's key, artifact `android-apk`; fails on any other signer |
| `cache-prune.yml` | after the build workflows | keeps the newest cache entry per key family |
| `build.yml.disable` | never | upstream's matching-decomp CI; needs the retail DOL, which this repository cannot have |

The checkout takes no submodules: `extern/musyx` is upstream's and unused by the port build
(`extern/musyx-port` is vendored).

## Runtime dependencies (Linux)

A Linux binary only runs where glibc and libstdc++ are at least as new as the ones it was linked
against, so release artefacts come from `linux-release.yml`, never a desktop build. The AppImage
bundles no libraries: FreeType, libpng and a Vulkan driver, X11 or Wayland come from the system.

## Signing identity (Android)

Releases are signed with this project's own key (`android/keystore.jks` + `keystore.properties`,
both untracked; `tools/make_android_keystore.sh` made them). Its SHA-256 is
`5c380a13d5bfc5c57a093a22d2ec70d62109a927f76b0bf7fe61db7d5428bd20`; `android.yml` checks it. CI
gets the key from the repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Android treats another signer as another app (an
update would need an uninstall, which deletes the save), so never sign a release with anything
else. The app id is `org.metroidprime2.port`.

## Version

`versionName`/`versionCode` in `android/app/build.gradle`, plus a `<release version=… date=…>`
entry (newest first) in `packaging/io.github.odrannnn.metroidprime2port.metainfo.xml`.

## Pipeline cache seed

Desktop builds embed `assets/initial_pipeline_cache.db`: the pipeline configs of the front
end, a scripted in-game pass and every campaign area, so a first start compiles the game's
shaders in the background instead of skipping draws as it meets them. Retail rows only (no
Remastered-style rows). When aurora bumps a pipeline config version (`clear.hpp`,
`gx/pipeline.hpp`, `rmlui/pipeline.hpp`), aurora ignores the seed and the `port_pipeline_seed`
test fails. Re-record from empty caches (needs a GPU path, ~2 h; no mods or texture packs):
`python3 tools/pipeline_seed.py record`, then the `merge` line it prints. `MP2_PIPELINE_SEED=0`
starts without the seed.

## Release checklist

1. Bump the version (above), commit, `git push origin port`.
2. Build every artefact from that commit, all at once:
   - Linux: `gh workflow run linux-release.yml --ref port -R Odrannnn/MetroidPrime2Port`, then
     `gh run download <id> -n metroid_prime2_port-linux` and `-n metroid_prime2_port-linux-aarch64`.
     Rename the tarballs `metroid-prime2-port-X-linux-{x86_64,aarch64}.tar.gz`; the AppImages keep
     their names. Each artifact also holds the binary's split-off debug info,
     `metroid-prime2-port-linux-<arch>.debug`: attach it as `metroid-prime2-port-X-linux-<arch>.debug`,
     so a crash log's `metroid_prime2_port+0x…` offsets stay readable with
     `addr2line -fCi -e metroid-prime2-port-X-linux-<arch>.debug 0x…`.
   - Windows: `windows.yml`; drop any `user/` folder from each artifact and zip the rest as
     `metroid-prime2-port-X-windows-{x86_64,arm64}.zip`.
   - macOS: `macos.yml`; `chmod +x` the bundle's executable (artifacts lose the mode bit) and zip
     the `.app` and `licenses/` as `metroid-prime2-port-X-macos-arm64.zip`.
   - Flatpak: `tools/make_flatpak.sh` (committed `port` branch), shipped as `MetroidPrime2Port.flatpak`.
   - Android: `gh workflow run android.yml --ref port -R Odrannnn/MetroidPrime2Port`, download
     `android-apk`, ship as `metroid-prime2-port-X-android-arm64.apk`.
   - iOS: `gh workflow run ios.yml --ref port -R Odrannnn/MetroidPrime2Port`, download
     `metroid_prime2_port-ios`, ship `MetroidPrime2Port.ipa` as is (unsigned, experimental).
3. Crash soak the release commit: `python3 tools/mpsoak.py --evidence-dir build/s-release-<date>/soak
   --user-dir <dir>`, where `<dir>/USA/Card A/` holds a G2ME save `.gci` (e.g. a copy of
   `/tmp/opencode/soak-user`; a new-game card leaves every cell on the front end); every row of
   `summary.tsv` `ok`, exit 0.
4. Check each artefact's version and that none holds game data (`unzip -l`, `--appimage-extract`),
   then `git tag -a vX` and `git push origin vX`.
5. Release notes: copy the previous `docs/release-notes/<version>.md` (the user's approved text,
   as published) and keep its shape exactly. Open with "This is an early release. Please report
   what you hit and attach the log (F1 > System > Log).", then the short disc line (no extension
   list, no "experimental" tags). Then **What changed**: bold one-line items with the issue numbers.
   Then **Downloads**: the asset table, with no sideloading note on the iOS row. Then **Known
   limitations**: only what is untested on real hardware. Leave out a title or intro paragraph, the
   decomp/Aurora blurb, the "first game" link and any link to PrimeDecomp/echoes. Commit the
   published text as `docs/release-notes/<version>.md`.
6. `gh release create vX --latest --notes-file …` with every asset passed explicitly, as a normal
   release, **not** `--prerelease`: the in-game update check (`platform/port_update_check.cpp`,
   setting `update_check`, env `MP2_UPDATE_CHECK=0`) polls `/repos/<repo>/releases/latest`, which
   GitHub's API answers only from non-pre-releases (it was a 404 while 0.6.0 and 0.6.1 were
   pre-releases). Confirm with `gh release view vX --json assets,isPrerelease` and
   `gh api repos/<repo>/releases/latest --jq .tag_name`. The Flatpak builds on
   `org.freedesktop.Platform` 25.08 with a vendored SDL3 (3.4.10, pinned in `flatpak/*.yml`).

The repository is public since 0.6.0. Real saves used as test fixtures (`tests/data/*.gci`,
`tests/fixtures/trilogy/*.bin`) stay untracked: they carry the game's banner and icon.
